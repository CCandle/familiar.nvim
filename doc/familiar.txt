1. Introduction                                           *familiar-introduction*

familiar.nvim is an experimental terminal-native companion. It lives inside
the editor without modifying file buffers, opening a chat UI, or producing
free-form dialogue.

The default avatar is "mote", an abstract glyph familiar limited to at most
three terminal rows. It expresses state through a compact face grammar,
optional ears/headwear, gestures, posture, and small Unicode effects instead
of relying on a detailed animal sprite.

The original 16x16 logical-pixel fox is still bundled as the alternate "fox"
avatar.

Current behavior reacts deterministically to typing, diagnostics, idle time,
viewport space, and rapid buffer switching. A constrained local AI policy is
planned, but is not a current runtime dependency.

===============================================================================
2. Requirements                                             *familiar-requirements*

- Neovim >= 0.12
- true-color terminal recommended
- lazy.nvim is the currently documented installation path
- Rust/Cargo is required only when building the optional familiar-core sidecar

No Ollama process or permanent daemon is required.

3. Setup                                                           *familiar-setup*

Example lazy.nvim spec: >lua

  {
    "CCandle/familiar.nvim",
    event = "VeryLazy",
    build = "cargo build --release -p familiar-core",
    opts = {},
  }
<

Equivalent explicit setup: >lua

  require("familiar").setup({
    enabled = true,
    debug = false,
    avatar = "mote",

    core = {
      enabled = true,
      bin = nil,
    },

    render = {
      frame_ms = 125,
      margin = 1,
      min_width = 36,
      min_height = 8,
      move_step = 2,
      warp_distance = 32,
    },

    telemetry = {
      snapshot_ms = 1200,
      max_visible_lines = 120,
    },
  })
<

Use the retained pixel fox instead: >lua

  require("familiar").setup({
    avatar = "fox",
  })
<

The public configuration surface is intentionally small during early
development.

4. Commands                                                     *familiar-commands*

:FamiliarStart                                                *:FamiliarStart*
    Start the familiar runtime if it is not already running.

:FamiliarStop                                                  *:FamiliarStop*
    Stop animation, telemetry, renderer resources, and the Rust child process.

:FamiliarToggle                                              *:FamiliarToggle*
    Toggle the runtime.

:FamiliarStatus                                              *:FamiliarStatus*
    Inspect the current avatar, animation, position, intent, and sidecar state.

:FamiliarDemo {animation} [duration_ms]                        *:FamiliarDemo*
    Temporarily force an existing avatar animation for visual inspection.
    Completion lists animations for the configured avatar. The duration
    defaults to 4000 ms and is bounded internally.

    Default Mote examples: >vim

      :FamiliarDemo idle 5000
      :FamiliarDemo inspect 5000
      :FamiliarDemo walk 3000
      :FamiliarDemo sleep 5000
      :FamiliarDemo wave 4000
      :FamiliarDemo cheer 4000
      :FamiliarDemo magic 4000
      :FamiliarDemo peek 4000
<

:checkhealth familiar                                      *familiar-health*
    Check Neovim version, true-color setting, avatar validation, sidecar
    discovery, and current runtime state.

5. Rendering                                                   *familiar-rendering*

The renderer supports two avatar kinds.

GLYPH AVATARS ~

The default Mote avatar stores a frame as one to three rows of styled text
segments. A segment has literal text and an optional semantic color role.

The visual design is intentionally highly abstract. For example: >

     /\_/\
    ( •ω• )
<

One-line states are used for compact motion, while three rows are reserved for
poses that benefit from extra height. Frames are padded into a stable
transparent render surface so their baseline does not jump as the content
changes height.

Special Unicode is decorative rather than structural. The default character
should remain legible even when a terminal/font combination renders some
non-core glyphs differently.

PIXEL AVATARS ~

The alternate fox avatar stores indexed logical pixels. Two vertical logical
pixels are packed into one terminal cell with Unicode half/full block glyphs
and true-color highlight groups.

Both render kinds use a borderless, non-focusable floating window as an
internal render surface. Untouched cells are transparent.

Safe placement currently favors blank space at the right side of the active
normal window. Wrapped rows are treated conservatively as occupied. If no safe
region exists, the familiar hides rather than covering the document.

6. Architecture                                               *familiar-architecture*

The Neovim frontend is intentionally Lua-native: autocmds, buffers/windows,
telemetry, floating render surface, highlights, and child-process lifecycle are
handled with Neovim APIs.

The optional `familiar-core` Rust child process owns normalized world state and
behavior policy. It communicates with Lua via versioned JSON Lines over stdio.
It is not a permanent system service and should exit with Neovim.

Rendering is presentation. The brain selects semantic intents such as `idle`,
`inspect`, `sleep`, or `focus`; the configured avatar decides how those intents
look. The default glyph actor and retained pixel fox therefore share the same
runtime behavior vocabulary.

See the repository `docs/` directory for ADRs, protocol details, avatar-format
direction, world-model design, and the future tiny-brain contract.

===============================================================================
7. Current limitations                                         *familiar-limitations*

- The Mote art and gesture grammar are still being tuned in real terminals.
- Safe placement currently favors blank space at the right side of the active
  normal window and does not yet model every virtual-text/UI obstacle.
- `peek` exists as an avatar animation but is not yet driven by a dedicated
  edge-interaction spatial behavior.
- Markdown/LaTeX structural telemetry is designed but not yet implemented.
- AI inference is intentionally not implemented yet.
- Headless CI can validate widths and schemas but cannot prove visual quality
  across terminal/font/theme combinations.
